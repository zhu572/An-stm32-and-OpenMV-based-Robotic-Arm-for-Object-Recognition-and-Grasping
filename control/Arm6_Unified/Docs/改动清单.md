## 2. 两处“看起来改算法、实际等价”的地方

### 2.1 IK 去掉 1° 扫描

PC 版 `arm_ik` 对 θ 做 1° 全范围扫描找最优接近方向，约 2000+ 次三角运算。
本工程改为解析结论：给定 `r1`，最大化 `dot(z_tool, z_target)` 的 θ 唯一确定为

```
theta0 = atan2(z_z, z_x·cos r1 + z_y·sin r1)
```

所以 phase 1/2 用常数个候选即可得到**同样**的解（不是近似），
只有候选全被限位剔除时才回退到 5° 粗扫描。**结果集不变，计算量降两个数量级。**

### 2.2 关节→舵机不再夹紧

`arm_set_joints()` 若换算出舵机角超出 `0..180`，直接回 `$ERR,LIMIT#` 并整帧拒绝。
夹紧会让机械臂走到一个与目标无关的姿态，比拒绝更危险。

### 2.3 关节限位与舵机零位必须是同一套坐标系

原 PC 端限位（j1 ±180、j2/j3 0..180、j4 ±90）配上"舵机 90° = 关节 0°"的映射后
**自相矛盾**：j1 实际只能到 ±90，j2/j3 的 0..180 又要求零位在 0°。
交付版本改为自洽组合：

| 关节 | 零位（舵机） | 关节范围 | 对应舵机区间 |
|---|---|---|---|
| j1 | 90° | −90..+90 | 0..180 ✓ |
| j2 | 0° | 0..180 | 0..180 ✓ |
| j3 | 0° | 0..180 | 0..180 ✓ |
| j4 | 90° | −90..+90 | 0..180 ✓ |

并在 `arm_init()` 增加了开机自检 `joint_map_coherent()`：任何一路的关节范围
映射不进该路舵机的 `angle_min/max` 就直接回 `$ERR,CONFIG#` 并停机，
避免"能编译、能跑、但每条闭环指令都撞 LIMIT"这种最难查的故障。

## 3. 有意没做的事

| 项 | 原因 |
|---|---|
| 没把 depth 强制写进帧协议（没有改 `view/main.py`） | 你说 view 不动；解析器同时兼容 6/7 字节帧，将来接测距只改 OpenMV 端 |
| 没动 `control/STM32_Arm6`、`control/ds`、`control/1/测` | 按约定原样保留对照 |
| 没有搬运/删除 HAL、CMSIS | 厂商代码用相对路径共享，避免两份容易漂移的副本 |
| 没做多帧滤波/目标跟踪 | 需要先有实测的视觉抖动数据 |
| 没做运动队列 | 沿用原设计“新目标覆盖旧目标”，PC 侧自己等 `$DONE#` |
| 没有编码器闭环 | 硬件没有；`$STATUS#` 仍是软件设定值 |

## 4. 已知风险（交付时请重点验证）

1. **未编译验证**：本环境 shell 不可用（沙箱授写 ACL 失败），我无法跑 Keil 或 gcc。
   `Tests/` 里的三个测试也未经运行。
2. **路径基准**：`Arm6_Unified.uvprojx` 在工程根目录，所以本工程源码写作
   `Core\Src\*.c`、`kin\*.c`（相对工程根目录），而厂商代码写作
   `..\STM32_Arm6\...`（上一层再进参考树）。**两者基准不同，改路径时别搞混**
   —— 这是第一版 Build 失败的原因（照搬了旧工程 `MDK-ARM\` 下的写法）。
   移动目录后需重新指向，或用 `Tools/materialize.py` 一次性自包含化。
3. **`arm_joint_from_servo` 用软件设定角**：舵机未到位时 FK 位姿与真实位姿有偏差。
4. **j2/j3 下限 0**：沿用 PC 端占位限位，会导致“低头抓低位”不可达；
   按机械实际行程放宽后需重新跑 `Tests/test_kin.c`。
5. **相机内参**：QQVGA 160×120 下的 fx/fy 是估计值，标定前反投影必然有系统误差。
6. **depth 单字节**：仅 0–255 mm。
