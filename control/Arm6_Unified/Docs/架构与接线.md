# 架构与接线

本文说明 `Arm6_Unified` 的坐标链路、模块边界、时序预算与标定清单。
原有 `../STM32_Arm6/docs/` 里的《从零开始》《配置与原理》仍适用于舵机层，本文只覆盖新增部分。

---

## 1. 数据流

```
                        ┌──────────────── USART1 (PA9/PA10) ───────────────┐
   电脑 ──ASCII $...#──▶│ 环形缓冲 256B ─▶ protocol.c ─▶ arm.c / pipeline.c │
                        └──────────────────────────────────────────────────┘

                        ┌──────────────── USART3 (PB10/PB11) ─────────────┐
   OpenMV ─二进制帧───▶│ 环形缓冲 64B ─▶ vision_frame.c ─▶ pipeline.c    │
                        └──────────────────────────────────────────────────┘

   pipeline.c:
     (u, v, depth)
        │ 反投影（相机内参）
        ▼
     cam 系点 P_c
        │ T_ee_cam（手眼标定）
        ▼
     EE 系点 P_e
        │ T_base_ee（由当前舵机设定角做 FK）
        ▼
     基座系目标位姿 T_base_obj
        │ arm_ik_pose()（闭式逆解 + 接近方向匹配）
        ▼
     j1..j4 (deg)
        │ g_joint_map（零位 / 方向）
        ▼
     舵机逻辑角 0..180 (0.1°)
        │ arm.c 插补 20 ms / 1°
        ▼
     TIM2 CH1-4 + TIM3 CH1-2 → 六路 50 Hz PWM
```

`T_base_obj = T_base_ee · T_ee_cam · T_cam_obj`，与 PC 端 `handeye.c` 完全一致，
只是把 `double` 换成 `float`、把 `fscanf` 读文件换成内置默认矩阵。

## 3. `$KIN#` 的字段

```
$KIN,auto,frames,solves,rejects,skipped,color,u,v,depth,j1,j2,j3,j4,err#
```

| 字段 | 含义 |
|---|---|
| `auto` | 是否在视觉闭环 |
| `frames` | 收到的合法视觉帧总数 |
| `solves` | 成功解算并下发动作的次数 |
| `rejects` | 解算被拒次数（见 `$TGT,ERR,n`） |
| `skipped` | 因 150 ms 限速被跳过的帧数 |
| `color` | 最近一帧的颜色字节（'B'=66 等） |
| `u,v,depth` | 最近一帧的像素与深度 |
| `j1..j4` | 最近一次成功解出的关节角，单位 0.1° |
| `err` | 接近方向残差，单位 mrad；-1 表示还没有成功解 |

## 4. 时序预算（72 MHz 内的 64 MHz 主频，无 FPU）

| 项 | 值 | 说明 |
|---|---|---|
| PWM 周期 | 20 ms | 硬件定时器输出，不占 CPU |
| 插补周期 | 20 ms | 每周期最多 1°，即 50 °/s |
| 单次完整解算 | 常数级候选：6 组表示 × 2 肘分支 ≈ 24 次 FK + 少量三角 | 取代 PC 版的 540 步扫描 |
| 解算限速 | 150 ms | `ARM_KIN_MIN_INTERVAL_MS`，一帧最多解一次 |
| 链路超时 | 2000 ms | 无合法命令则保持脉宽并锁定运动 |
| 视觉半帧超时 | 150 ms | `VISION_TIMEOUT_MS` |

**为什么不能照搬 PC 端的 1° 扫描**：PC 版 `arm_ik` 在 θ∈[-90°,450°] 以 1° 扫描，
每个 θ 还要解 2 个肘分支并做 FK 回代，共约 2000+ 次三角函数密集计算；
在 64 MHz 无 FPU 的 M3 上远超 20 ms，会把插补拖垮。

替代依据（解析结论，非近似）：
给定方位角 `r1`，末端 z 轴为 `(cosθ·cos r1, cosθ·sin r1, sinθ)`，
使 `dot(z_tool, z_target)` 最大的 θ 恰为

```
theta0 = atan2(z_z, z_x·cos r1 + z_y·sin r1)
```

因此 phase 1 用 `theta0` 与 `π - theta0`（配合 `(r1, L)` / `(r1+π, -L)` 两种
等价表示与 θ±2π）即可覆盖全部方向精确解；phase 2 直接用 `theta0` 取最小残差；
只有这些候选全被关节限位剔除时才回退到 5° 粗扫描（phase 3，正常路径不进入）。

## 5. 引脚与电气

| 功能 | 引脚 | 备注 |
|---|---|---|
| S1..S4 | PA0, PA1, PA2, PA3 | TIM2 CH1..CH4，50 Hz |
| S5, S6 | PA6, PA7 | TIM3 CH1, CH2 |
| 电脑 UART | PA9 (TX), PA10 (RX) | USART1，115200 8N1 |
| OpenMV UART | PB10 (TX), PB11 (RX) | USART3，115200 8N1 |
| SWD | PA13, PA14 | 已 `SWJ_NOJTAG`，保留调试 |
| 舵机电源 | 外部 5 V | **不得**从 GPIO 或 3.3 V 取电，必须共地 |

USART2 的 PA2/PA3 已被 S3/S4 占用，所以视觉链路必须走 USART3。

## 6. 标定清单（按顺序做，全部替换 `[TEMP]`）

0. **先确认开机自检通过**：`arm_init()` 会校验 `g_joint_map` 与 `KIN_Jn_MIN/MAX`
   是否能映射进该路舵机的 `angle_min/max`。不自洽时直接回 `$ERR,CONFIG#` 并停机 ——
   这时改 `arm_config.c` 的 `zero_tenths/sign` 或 `kin_config.h` 的限位，两边必须同一套坐标系。
1. **关节零位**：手动把每个关节摆到你的"0°"姿态，读 `$STATUS#` 的设定值，
   写入 `Core/Src/arm_config.c` 的 `g_joint_map[k].zero_tenths`。
2. **关节方向**：发 `$S,2,100#`，若关节朝负方向动，把对应 `sign` 改为 `-1`。
3. **舵机行程**：实测每路的实际可用脉宽与角度，改 `g_servo_config` 的
   `pulse_min_us / pulse_max_us / angle_min_tenths / angle_max_tenths`。
4. **连杆尺寸**：卷尺量 `KIN_A1..A4`（mm）与肩偏置 `KIN_P`，改 `kin/kin_config.h`。
5. **关节限位**：按机械实际行程改 `KIN_J2_MIN` 等（当前 j2/j3 ≥ 0 会让"低头抓低位"不可达）。
6. **相机内参**：棋盘格标定 OpenMV（`QQVGA 160×120`），改 `KIN_CAM_FX/FY/CX/CY`。
   ⚠️ 现在按 160×120 取值，与 PC 端原来的 320×240 假设不同。
7. **手眼标定**：得到 `T_ee_cam`（4×4）后替换 `kin/handeye.c` 的 `g_default_calib`。
8. **深度**：`ARM_DEFAULT_DEPTH_MM` 先给实测平面距离；接上测距后改用 7 字节帧。
9. 每一步都用 `$TARGET,80,60,<depth>#` 单独验证，确认 `$TGT,OK` 且关节在手算范围内。
10. 最后才 `$AUTO,1#` 上真实视觉。

## 7. 失败与互锁

| 情况 | 行为 |
|---|---|
| 未 `$ON#` 就发动作/`$AUTO,1#` | `$ERR,DISABLED#`，不动 |
| 解算超出舵机可达范围 | `$ERR,LIMIT#`，整帧拒绝，**不夹紧** |
| 目标不可达 | `$TGT,ERR,2#`，设定值不变 |
| 接近方向残差 > 350 mrad | `$TGT,ERR,3#`，设定值不变 |
| 2 s 无合法命令 | `$WARN,LINK_TIMEOUT,HOLD#`，保持脉宽、退出闭环，需重新 `$ON#` |
| UART1 溢出/错误 | `$ERR,RX_LOSS#`，停止插补、退出闭环 |
| UART3 溢出/错误 | 静默丢弃半帧并重新同步（视觉链路不该锁死机械臂） |
| `$STOP#` / `$OFF#` / 任意直接运动命令 | 退出视觉闭环 |

`$STOP#` 保留最近脉宽，`$OFF#` 撤掉脉冲（有重力负载会掉下来）。两者都不是硬件急停。
